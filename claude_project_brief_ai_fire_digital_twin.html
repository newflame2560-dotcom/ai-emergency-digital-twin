🔥 Claude Project Brief

AI Fire Emergency Digital Twin

เอกสารสรุปสำหรับส่งให้ Claude เพื่อเริ่มสร้าง Prototype ระบบจำลองพื้นที่อาคารจริง สำหรับแผนฉุกเฉินกรณีเพลิงไหม้ โดยใช้แนวคิด Google Maps + Floor Plan/BIM + Safety Layer + AI Simulation

Web App ต้นแบบระบบใช้งานจริง
90 วัน กรอบพัฒนา MVP
7 หน้า หน้าจอหลักใน Prototype
AI Support ช่วยวิเคราะห์ ไม่ใช่ตัดสินใจแทน

1. Project Summary

ภาพรวมที่ Claude ต้องเข้าใจก่อนเริ่มสร้างโปรเจกต์

Project Context

เป้าหมายระบบ

สร้าง Web Application สำหรับจำลองพื้นที่อาคารจริง เพื่อใช้วางแผน ฝึกซ้อม วิเคราะห์ และปรับปรุงแผนฉุกเฉินกรณีเพลิงไหม้

ผู้ใช้งานหลัก

จป.วิชาชีพ, Fire Warden, Area Warden, Incident Commander, Facility, Maintenance, Security และผู้บริหาร

ผลลัพธ์ที่ต้องการ

Prototype ที่คลิกดูได้ มีข้อมูลจำลองสมจริง เห็นภาพ Dashboard, Scenario, Evacuation และ AI After Action Review

หลักการออกแบบระบบ Google Maps ใช้เป็นฐานข้อมูลพื้นที่ภายนอกอาคาร ส่วนข้อมูลภายในอาคารต้องใช้ Floor Plan, CAD หรือ BIM ขององค์กรเอง แล้วนำมาซ้อนเป็น Safety Layer เพื่อให้ AI วิเคราะห์และจำลองเหตุการณ์ได้แม่นยำขึ้น

2. System Concept

โครงสร้างแนวคิดของ Digital Twin สำหรับงานเพลิงไหม้

Digital Twin Layers

Google Maps Layer

พื้นที่ภายนอก อาคาร ถนน ทางเข้าออก จุดจอดรถดับเพลิง และจุดรวมพล

Building Layer

Floor Plan, ห้อง, โซน, ทางเดิน, ประตู, บันได และทางหนีไฟ

Safety Layer

ถังดับเพลิง, Alarm, Detector, Emergency Light, Risk Zone และ Emergency Team

AI Simulation Layer

สร้าง Scenario, วิเคราะห์เส้นทางอพยพ, จุดคอขวด และสรุป AAR

3. MVP Scope

ขอบเขต Prototype รอบแรก ไม่ต้องเชื่อม API จริง แต่ต้องดูเหมือนระบบใช้งานจริง

MVP Requirement
หน้าจอ เป้าหมาย องค์ประกอบที่ควรมี
Overview Dashboard ดูภาพรวมความพร้อมของอาคารและแผนฉุกเฉิน KPI Cards, Risk Summary, Drill Status, Open Corrective Actions
Building Map แสดงพื้นที่จริงรอบอาคาร Placeholder Map, ทางเข้าออก, จุดรวมพล, ถนน, จุดเข้าถึงรถฉุกเฉิน
Floor Plan & Safety Layer ดูข้อมูลภายในอาคารและอุปกรณ์ฉุกเฉิน ชั้นอาคาร, ห้อง, ทางหนีไฟ, อุปกรณ์ฉุกเฉิน, Risk Zone
Fire Scenario Builder สร้างเหตุจำลองเพลิงไหม้ เลือกจุดเกิดเหตุ, ระดับเหตุ, จำนวนคน, ทางออกที่ใช้ไม่ได้, ผู้บาดเจ็บ
Evacuation Simulation แนะนำทางอพยพและประเมินผลกระทบ เส้นทางหลัก/สำรอง, จุดคอขวด, เวลาคาดการณ์, พื้นที่เสี่ยง
Drill Dashboard บันทึกและติดตามผลการซ้อม Timer, จำนวนคนครบ/ไม่ครบ, สถานะทีม, Timeline เหตุการณ์
AI After Action Review สรุปบทเรียนหลังซ้อม ข้อค้นพบ, สาเหตุ, Corrective Action, Owner, Due Date

Phase 2: Safety Layer & Emergency Asset Mapping

สัปดาห์ที่ 4-5

  • จำลอง AI Scenario ด้วยข้อมูลตัวอย่าง
  • แนะนำเส้นทางอพยพหลัก/สำรอง
  • วิเคราะห์จุดคอขวดและพื้นที่เสี่ยงติดค้าง
4

Phase 4: Drill Dashboard & After Action Review

สัปดาห์ที่ 9-12
  • บันทึกเวลาแจ้งเหตุ เริ่มอพยพ ถึงจุดรวมพล และตรวจนับครบ
  • แสดง Dashboard สรุปผลการซ้อม
  • สร้าง AI AAR Report และ Corrective Action Plan

6. Data Model เบื้องต้น

ชุด Entity ที่ควรใช้เป็นฐานข้อมูลในรอบพัฒนา

Database Schema

Building

ข้อมูลอาคาร พิกัด จำนวนชั้น ประเภทอาคาร

Floor

ข้อมูลชั้น แปลน พื้นที่ และจำนวนคน

Zone / Room

ห้อง พื้นที่เสี่ยง ระดับความเสี่ยง และผู้รับผิดชอบ

Exit / Stair

ประตู ทางออก บันได สถานะใช้งานได้/ไม่ได้

Assembly Point

จุดรวมพล ความจุ และเส้นทางเข้าถึง

Emergency Asset

ถังดับเพลิง Hose Reel Alarm Detector Emergency Light

Emergency Team

รายชื่อทีม บทบาท หน้าที่ และพื้นที่รับผิดชอบ

การซ้อม เวลา KPI ผลลัพธ์ และข้อบกพร่อง

Scenario

Evacuation Route

เส้นทางหลัก สำรอง จุดคอขวด และเวลาคาดการณ์

AAR Report

สรุปผลหลังซ้อม บทเรียน และข้อเสนอแนะ

Corrective Action

มาตรการแก้ไข Owner Due Date และสถานะการปิดงาน

7. Safety Guardrails

ข้อจำกัดด้านความปลอดภัยที่ Claude ต้องสะท้อนในระบบ

Critical Safety Rule

สิ่งที่ระบบต้องทำ

  • ระบุชัดว่า AI เป็น Decision Support เท่านั้น
  • ให้ผู้บัญชาการเหตุการณ์เป็นผู้ตัดสินใจขั้นสุดท้าย
  • แนะนำการอพยพออกจากพื้นที่อันตราย ไม่ใช่ให้บุคคลทั่วไปเข้าไปในพื้นที่เสี่ยง
  • แสดงคำเตือนเมื่อ Scenario มีความเสี่ยงสูง

สิ่งที่ระบบต้องหลีกเลี่ยง

  • ห้ามแนะนำให้พนักงานทั่วไปกลับเข้าอาคาร
  • ห้ามสั่งการดับเพลิงแทนผู้มีหน้าที่
  • ห้ามทำให้คำแนะนำ AI ดูเหมือนคำสั่งทางกฎหมายหรือคำสั่งฉุกเฉินจริง
  • ห้ามละเลยแผนฉุกเฉินที่องค์กรอนุมัติไว้แล้ว
ข้อความเตือนที่ควรแสดงในระบบ คำแนะนำจาก AI เป็นข้อมูลสนับสนุนการตัดสินใจเท่านั้น การตัดสินใจจริงต้องอยู่ภายใต้ผู้บัญชาการเหตุการณ์ แผนฉุกเฉินที่ได้รับอนุมัติ และข้อกำหนดความปลอดภัยขององค์กร

โปรเจกต์นี้ชื่อ:

AI Fire Emergency Digital Twin

เป้าหมายของโปรเจกต์:
สร้าง Web Application สำหรับจำลองพื้นที่อาคารจริง เพื่อใช้วางแผนฉุกเฉินกรณีเกิดเหตุเพลิงไหม้ โดยใช้แนวคิด Digital Twin ผสาน Google Maps, Floor Plan, Safety Layer และ AI Simulation เพื่อช่วยให้ จป., ทีมฉุกเฉิน, Fire Warden และผู้บัญชาการเหตุการณ์ สามารถจำลองสถานการณ์ วิเคราะห์เส้นทางอพยพ และสรุปผลการฝึกซ้อมได้อย่างเป็นระบบ

บริบทของระบบ:
ระบบนี้ไม่ได้ใช้ Google Maps เพื่อสร้างข้อมูลภายในอาคารทั้งหมดโดยอัตโนมัติ แต่ใช้ Google Maps เป็นฐานแผนที่ภายนอกอาคาร เช่น ตำแหน่งอาคาร ถนน ทางเข้าออก จุดรวมพล และพื้นที่โดยรอบ ส่วนข้อมูลภายในอาคารจะมาจาก Floor Plan, CAD, BIM หรือข้อมูลที่องค์กรจัดเตรียมเอง

แนวคิดหลัก:
Google Maps = พื้นที่จริงภายนอกอาคาร
Floor Plan / BIM = โครงสร้างภายในอาคาร
Safety Layer = ข้อมูลความปลอดภัย เช่น ทางหนีไฟ จุดรวมพล ถังดับเพลิง Fire Alarm Detector จุดเสี่ยง
AI Simulation = วิเคราะห์สถานการณ์เพลิงไหม้ แนะนำเส้นทางอพยพ และสรุป After Action Review

กลุ่มผู้ใช้งาน:

2. Fire Warden / Area Warden
3. Incident Commander
4. Facility / Maintenance
5. Security
6. ผู้บริหารที่ต้องการดู Dashboard

First Message to Claude วางเป็นคำสั่งแรกในแชท 
เริ่มสร้าง Prototype ระบบ AI Fire Emergency Digital Twin ตาม Project Instructions

ขอให้เริ่มจาก:
1. สรุป Architecture ของระบบ
2. ออกแบบ Sitemap / Navigation
3. สร้าง UI Prototype หน้า Overview Dashboard
4. ใช้ข้อมูลจำลองภาษาไทย
5. ทำหน้าจอให้ดูเหมือนระบบใช้งานจริงสำหรับงานแผนฉุกเฉินเพลิงไหม้

ข้อกำหนดเพิ่มเติม:
- สร้างเป็น single-page web app ในไฟล์เดียว
- ใช้ HTML, CSS และ JavaScript ทั้งหมดใน artifact เดียว
- ไม่ต้องเชื่อม Google Maps API จริง ให้ใช้ placeholder map ก่อน
- ไม่ต้องเชื่อม AI API จริง ให้จำลองผลลัพธ์ AI ด้วยข้อมูลตัวอย่าง
- ต้องคลิกเปลี่ยนหน้าหลักได้ เช่น Dashboard, Building Map, Floor Plan, Scenario, Evacuation, Drill, AAR Report
- UI ต้องดูทันสมัย สะอาด เหมาะกับงาน Safety และใช้ภาษาไทยเป็นหลัก
- ใส่ข้อความเตือนว่า AI เป็นเพียง Decision Support ไม่ใช่ผู้สั่งการเหตุฉุกเฉิน

หลังจากสร้างหน้าแรกแล้ว ให้เสนอขั้นตอนถัดไปสำหรับหน้า Building Map, Floor Plan, Scenario Builder และ Drill Dashboard

Next Iteration
Development Continuation Prompt ใช้ต่อหลังได้ Prototype หน้าแรก 
ขยาย Prototype ให้ครบทุกหน้าจอตาม MVP Scope

ต้องการให้เพิ่ม:
1. Building Map Page
   - แสดงอาคารจำลองบนแผนที่
   - มีจุดเข้าออกอาคาร
   - จุดจอดรถฉุกเฉิน
   - Assembly Point A / B
   - เส้นทางรถดับเพลิงเข้าอาคาร

2. Floor Plan & Safety Layer Page
   - เลือกชั้น 1-4 ได้
   - แสดงห้องหลัก ทางเดิน บันได ทางหนีไฟ
   - ปักจุดถังดับเพลิง Alarm Detector Emergency Light
   - แสดงพื้นที่เสี่ยงด้วยสี High / Medium / Low

3. Fire Scenario Builder Page
   - เลือกจุดเกิดเหตุ
   - เลือกระดับความรุนแรง
   - กำหนดจำนวนคนในอาคาร
   - เลือกทางออกที่ใช้งานไม่ได้
   - กดปุ่ม Generate Scenario เพื่อให้ระบบจำลองผลลัพธ์

4. Evacuation Simulation Page
   - แสดงเส้นทางอพยพหลักและสำรอง
   - แสดงเวลาคาดการณ์
   - แสดงจุดคอขวด
   - แสดงพื้นที่ที่ต้องให้ทีมช่วยเหลือ

5. Drill Dashboard Page
   - Timer สำหรับเหตุการณ์
   - บันทึกเวลาแจ้งเหตุ เริ่มอพยพ ถึงจุดรวมพล ตรวจนับครบ
   - จำนวนคนครบ / ไม่ครบ
   - สถานะทีมฉุกเฉิน

6. AI After Action Review Page
   - สรุปจุดแข็ง
   - สรุปข้อบกพร่อง
   - Root Cause เบื้องต้น
   - Corrective Action
   - Owner และ Due Date

ให้คง Style เดิม และทำให้ทุกหน้าเชื่อมโยงกันด้วยข้อมูลจำลองชุดเดียวกัน
